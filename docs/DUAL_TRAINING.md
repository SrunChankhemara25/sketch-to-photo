# Quality-first training: one notebook, both directions

Use **notebooks/sketch2photo_master_training.ipynb** in Google Colab. It is the
project's only training notebook and covers both directions.

## What is new

For each direction, train and compare:

1. A skip-connected U-Net with paired reconstruction, perceptual and gradient losses.
2. A residual generator with a conditional PatchGAN and paired losses.
3. A pretrained InstructPix2Pix editor with separate rank-32 LoRA adaptation.

This produces six model candidates. The notebook compares them on the same splits,
tunes learning rate and weight decay for the validation winner in each direction,
retrains the chosen settings, and exports all three selected approaches per direction.
The default model is selected by validation LPIPS, not by assuming diffusion wins.
The two directions are two tasks, not two architectures.

**This is an improved experimental design, not a proven improved model.**
No full dataset training has been run here. A short pilot verifies execution, not
photorealism. Neither perfect artwork nor exact original colours can be guaranteed.

## Dataset decision

The default `DATA_SOURCE='coco_fs2k'` combines:

- COCO: up to 60,000 training / 2,000 validation / 2,000 test photos. Pencil targets
  are synthetic, generated by the project's existing renderer.
- FS2K: 2,104 real photo–artist-sketch portrait pairs. Keep its official test split;
  hold out 20% of its training set by drawing style for validation. Actual counts
  are recorded, not assumed. It is not claimed to be identity-independent.

FS2K adds genuine drawing supervision; it does not cover general artistic scenes.
COCO adds scene diversity but cannot teach real hand-drawing style by itself.
Training samples real pairs at 25% when both domains exist; this repeats a small
portrait set, so monitor overfitting. Validation weights domains equally and test
reports separate domain scores. Exact-duplicate checks do not detect all near duplicates.

Download/extract FS2K from its [official repository](https://github.com/DengPingFan/FS2K)
and set `FS2K_ROOT`, or explicitly enable `DOWNLOAD_FS2K=True`.
The public archive download has not been verified end-to-end locally. Failure stops
the notebook with instructions; it does not silently switch to synthetic data.

For a better licensed paired dataset, use `DATA_SOURCE='paired_csv'`:

```csv
photo,sketch,split,group_id
photos/person01.jpg,drawings/person01.png,train,person01
photos/person02.jpg,drawings/person02.png,val,person02
photos/person03.jpg,drawings/person03.png,test,person03
```

Paths are relative to the CSV. Pairs must be aligned and have matching aspect ratios.
Keep all versions of one source/person in one split. These three rows illustrate a
format, not enough training data. Review dataset/image terms before redistribution;
a code repository's MIT license is not a blanket license for its source photographs.

## Run in Colab

1. Upload the master notebook and choose a GPU runtime. Run setup in a fresh runtime.
   It keeps Colab's matching torch/torchvision pair and records an exact environment lock.
2. Verify the student name. Configure Drive storage, data source and FS2K availability.
3. Leave `MODE='pilot'` initially. Inspect both synthetic and artist training targets.
   If you dislike the target style, improve the dataset before training.
4. Run the pilot training, tuning and validation sections. Inspect faces, hands,
   identity, colour plausibility, pencil strokes and failure examples.
5. For the real experiment, record `FULL_RUN_REVIEW`, change to `MODE='full'`,
   and run the notebook again. Pilot/full have separate directories.
6. Full budgets are 30 U-Net epochs, 40 GAN epochs and 5 diffusion epochs, with early
   stopping based on shared validation LPIPS. These are starting budgets, not
   guarantees. The expanded experiment can exceed the assignment's free-Colab
   scope guidance; confirm that scope with the teacher. Early stopping can end a
   model before its maximum epoch count; more epochs after validation stalls are
   not expected to improve quality.
7. Run the six LR/weight-decay trials for the validation winner in each direction.
   Their results are recorded; selected settings are retrained and compared with
   the original candidate on validation.
8. Freeze choices, fill `TEST_REVIEW_NOTE`, enable `RUN_TEST_EVALUATION` and leave
   `TEST_LIMIT=None` for full held-out evaluation. Do not tune using test results.
9. Export the model bundle. Keep original checkpoints until the new results justify replacement.

Training resumes from Drive for the same experiment/data/configuration/source.
Changed settings require a new experiment name. Resume files use pickle and must
only be loaded from your own trusted runs. CNN inference exports use safe
`weights_only=True` loading; diffusion adapters use safetensors.

512px is the pretrained editor's working resolution. Increasing a number or enlarging
the final display does not create genuine high-resolution detail. Actual memory,
runtime and production visual quality still require a Colab run.

## One deployable web launcher

There is now only **app.py**, implemented with Streamlit. It can run on your computer
or a deployed Python web service. The old extra launcher was consolidated into it.

Without an installed new default bundle:

```bash
python app.py
```

runs the original app/checkpoints. After training, extract the export contents into
`checkpoints/quality_study/`. For the new dependencies use Python 3.11 or 3.12:

```bash
python3.12 -m venv .venv-diffusion
source .venv-diffusion/bin/activate
pip install -r requirements-diffusion.txt
python app.py
```

The normal URL is http://localhost:8501. The app discovers the default bundle
automatically. Choose **Original checkpoints** or **New trained models** in the sidebar.
The bundle location is also editable in the sidebar. The new study app offers both
directions and all three approaches. Preview/download
are the same actual prediction; sketch input is white-paper grayscale, not the
legacy dark representation. No saved-original-photo retrieval is used in the new app.
Only diffusion responds to the optional colour/text description. First use downloads
the pretrained base; adapters alone are not complete standalone models.

## Evidence and assignment requirements

The notebook implements three PyTorch approaches, shared splits/preprocessing,
seeded training, checkpoint/resume, learning-rate and regularization trials,
training/validation curves, trainable parameter and hardware/time reports, common
MAE/PSNR/SSIM/LPIPS metrics, comparison figures and worst-case analysis.
PSNR is capped at 100 dB for exact matches. Colourfulness is descriptive, not a
quality score. The fixed validation subset and full/subset test counts are recorded.
Different architectures have different training budgets; tuning costs are separate.

Local mechanical checks covered notebook compilation, tiny CNN forward/backward
updates in both directions, completed-run resume, model export/reload, FS2K path/split
fixtures, Streamlit rendering and server startup, and real tiny diffusion
backward/LoRA save-load/inference.
The CNN metric check used a dummy metric; actual LPIPS weights, full FS2K download,
CUDA memory, end-to-end Colab execution and production output quality remain unverified.

The full assignment is NOT completed by producing a notebook. After real training:

- add measured result tables and discuss why a method won;
- document bias, uncertainty, failure cases and possible pretrained-data overlap;
- provide actual working download links for large weights;
- prepare the required 10–20 slides and presentation;
- maintain genuine commits, cite technical sources and disclose AI assistance.

Do not insert fabricated measurements or call step-zero selections successful
training. Do not compare old 128px metrics directly with the new test protocol.
